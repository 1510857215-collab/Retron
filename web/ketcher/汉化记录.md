## 一、调研结论（关键）：官方包**没有** i18n

任务书里列的 a/b 两条路（初始化传 `{locale:'zh'}`、显式引入语言资源）在本项目用的版本上**都不存在**，原因如下（全部为本地实测）：

| 检查项 | 结果 |
|---|---|
| `ketcher-standalone@3.18.0` / `ketcher-react@3.18.0` / `ketcher-core@3.18.0` 里有无 `locale/locales/i18n/translation` 目录 | **无** |
| `ketcher-react/dist/index.js` 里 `i18next` / `react-i18next` / `useTranslation` / `translation` 出现次数 | **0** |
| `ketcher-react` 的 `dependencies` 里有无 `i18next` / `react-i18next` | **无**（依赖表里根本没有） |
| `ketcher-react` 的 `Editor` / `EditorProps` 有无 `locale` / `language` 之类入参 | **无**（`EditorProps` 只有 `onInit` / `onSetKetcherId` 等） |
| 界面文案怎么存的 | 直接**硬编码英文字面量**，例如 `jsx(TopToolbarIconButton, { title: "Undo", ... })`、`title: 'Aromatize'` |

**结论**：EPAM 发布的这份 `dist` 是把 i18n 剥掉/固定成英文的版本，没有运行时切换语言的入口。
→ 只能走任务书里的 (c)：**在打包阶段把关键界面词条替换成中文**。

## 二、采用的方案：构建期「展示位文案替换」

思路：写一个 esbuild `onLoad` 插件，在打包前拦截 `ketcher-react` / `ketcher-core` 的 dist 源码，把**展示属性**上的英文整串替换成中文，再交给 esbuild 正常打包成单文件 IIFE。

只替换下面这几类「展示位」，**且要求整串精确匹配**，因此不会误伤内部标识符、元素符号、化学值：

| 替换类别 | 处理方式 | 说明 |
|---|---|---|
| `title` / `label` / `placeholder` / `tooltip` / `children` 属性 | 正则 `prop:\s*(['"])英文\1` → 中文 | 工具提示、菜单项、按钮、对话框标签 |
| `enumNames: [...]` 数组内 | 仅替换方括号内的显示名 | 设置面板下拉项。**`enum` 的真实取值绝不动**，逻辑不受影响 |
| 环模板名 | 替换 MOL 字符串首行 `"Benzene\n  Ketcher` → `"苯\n  Ketcher` | 底部环模板工具提示 |
| `Dialog` 组件字符串按钮 | 整段替换 `value=` 表达式，增加中文名兜底表 | 按钮 ID（`OK`/`Cancel`）参与 `isButtonOk`/`exit` 判断，**只改显示名、不改 ID** |

### 为什么不用「DOM 文案补丁」（任务书里的退路）
正规重打包**完全可行且已跑通**（见下），因此不需要退路方案。

## 六、还没汉化的地方（如实说明）

| 位置 | 未译内容 | 原因 |
|---|---|---|
| **隐藏的大分子库**（`disableMacromoleculesEditor: true` 后不可见） | `Bases` `Sugars` `Phosphates` `Nucleotides` `Presets` `Favorites` `DNA` `RNA` `Create Antisense Strand` `Single Bond (1)` | 这些控件**不可见**（实测 `getBoundingClientRect` 宽高为 0 / 父层隐藏），且属大分子编辑器；译了也看不到，未做 |
| 设置面板个别下拉值 | `low`（图像分辨率）、`Terminal and Hetero`（显示氢标签） | 它们是**参与逻辑判断的真实取值**（如 `showHydrogenLabels === 'Terminal and Hetero'`），翻译会破坏设置回读，**故意不译** |
| 设置面板单位 | `px`、`% of length` | 单位符号，业界通例保留 |
| 「扩展表」对话框 | `Atom Generics` `Acyclic` `Cyclic` … | 这些字符串**同时被用作逻辑比较键**（`mainTitles.includes(title)`、`isGenericGroup()`），翻译会导致功能错乱，**故意不译** |
| 元素周期表 104–118 号元素名 | `𬬻 𬭊 𬭳 …` | 已译，但属 CJK 扩展 B 区生僻字，个别字体可能显示为方框（`SimSun-ExtB` 等可正常显示） |
| 内部标题/品牌 | `Ketcher` `EPAM Life Sciences` `Indigo Toolkit` `BIOVIA 2009/2017` | 品牌名与格式名，不译 |

**「不可见」的判定**：用 CDP 对每个 `[title]` 元素取 `getBoundingClientRect()` + `getComputedStyle`，
宽高为 0 或 `display:none`/`visibility:hidden` 的即判为不可见。上述未译项全部落在不可见集合内。

## 八、注意事项

1. **必须走 HTTP 打开**（沿用原记录）：Indigo 引擎用 `blob:` URL 起 Web Worker，`file://` 下会被浏览器拒绝。
2. 重新汉化/补词条：改 `tools/tmp/ketcher-zh-dict.json`（`_enumNames` 为设置下拉项，`_templates` 为环模板名），
   再 `node tools/tmp/build_ketcher_zh.mjs` 即可，约 33 秒。
3. 词典里凡是「会被当逻辑键用的字符串」都**不要**放进去，否则会破坏功能（详见第六节）。
4. `ketcher-app.js` 仍含第三方开源许可证声明（Apache-2.0 等），正式发布前建议补 `THIRD-PARTY-LICENSES`
   （Ketcher 为 Apache-2.0，Indigo 亦为 Apache-2.0）—— 与本次汉化无关，沿用原记录遗留项。
