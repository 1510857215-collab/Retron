## 二、三条途径的实测结果

| 途径 | 命令/地址 | 结果 | 判定 |
|---|---|---|---|
| **A. npm 包** | `npm install ketcher-standalone@3.18.0 --registry=https://registry.npmmirror.com` | 12 秒装好（node v22 + npm 10）。`dist/` 里是 **ESM 模块**（`dist/main.js` 引用 `ketcher-core` 等裸模块名），**没有可直接 `<script>` 引用的 UMD/IIFE 打包文件**，也没有 `.min.js` | ⚠️ 不能单独用，但可作为打包素材 ✅ |
| **B. GitHub Releases** | `https://github.com/epam/ketcher/releases/download/v3.18.0/ketcher-standalone-3.18.0.zip`（33.4 MB） | 地址可达、资产确实存在（另有 `ketcher-standalone.zip` 33.0 MB）。但实测速度约 **17 KB/s**，两次 600 s 超时（各只下到约 10 MB / 35 MB），放弃 | ❌ 太慢，放弃 |
| **C. jsDelivr** | `https://cdn.jsdelivr.net/npm/ketcher-standalone@3.18.0/...` | `data.jsdelivr.com`（元数据 API）可达，但 `cdn.jsdelivr.net`（真正的文件 CDN）**连接被重置**（`curl: (35) Recv failure: Connection was reset`，HTTP 000） | ❌ 不可达 |

**最终采用的途径：A 路线 + 本地 esbuild 打包。**

即：用 npm（淘宝镜像，秒级）拿到 EPAM **官方已经编译好的 dist 包**，再用 esbuild 把这几块拼成一个自包含的 IIFE 文件。
**没有从 React 源码编译 Ketcher**，所以耗时只有几十秒，符合"不要自己从源码构建"的要求。

## 四、关键步骤

### 1. 装依赖（临时目录 `tools/tmp/`）

```bash
cd C:/Users/zzl/Desktop/hx/tools/tmp
npm init -y
npm install ketcher-standalone@3.18.0 ketcher-react@3.18.0 ketcher-core@3.18.0 \
            react@18 react-dom@18 esbuild events buffer process stream-browserify \
            util path-browserify string_decoder \
            --registry=https://registry.npmmirror.com --no-audit --no-fund
```

> `events`/`buffer`/`process` 等是 Node 内置模块的浏览器 polyfill —— `ketcher-core` 里有
> `import { EventEmitter } from 'events'`，不打补丁浏览器会直接报错。

### 2. 入口文件 `tools/tmp/ketcher-entry.jsx`

```jsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import { Editor } from 'ketcher-react';
import { StandaloneStructServiceProvider } from 'ketcher-standalone';
import 'ketcher-react/dist/index.css';

// 全离线：Indigo 引擎（WASM）已内嵌在 ketcher-standalone 的打包里，不需要任何网络请求。
const structServiceProvider = new StandaloneStructServiceProvider();

function App() {
  return React.createElement(Editor, {
    staticResourcesUrl: '',
    structServiceProvider,
    disableMacromoleculesEditor: true,   // 只用小分子画板，关掉高分子的 PDB 联网下载入口
    onInit: (ketcher) => {
      window.ketcher = ketcher;
      window.__ketcherReady = true;
      document.dispatchEvent(new CustomEvent('ketcher-ready'));
    },
  });
}

const container = document.getElementById('ketcher-root');
createRoot(container).render(React.createElement(App));
```

### 3. 全局变量补丁 `tools/tmp/inject-shim.js`

```js
// esbuild --inject：把 Node 的 process / Buffer 全局变量替换为浏览器 polyfill 的 import
export { default as process } from 'process';
export { Buffer } from 'buffer';
```

### 4. 打包命令

```bash
cd C:/Users/zzl/Desktop/hx/tools/tmp
node node_modules/esbuild/bin/esbuild ketcher-entry.jsx \
  --bundle --format=iife --platform=browser --target=es2020 --jsx=transform \
  --define:process.env.NODE_ENV='"production"' \
  --define:global=globalThis \
  --inject:inject-shim.js \
  --minify --legal-comments=none \
  --outfile="../../web/ketcher/ketcher-app.js"
```

esbuild 会同时把 `ketcher-react/dist/index.css` 输出成同名的 `ketcher-app.css`。

**踩过的坑（按出现顺序）**

| 报错 | 原因 | 解决 |
|---|---|---|
| `Could not resolve "events"` | `ketcher-core` 引用了 Node 内置模块 | 装 `events`（及 `buffer`/`process` 等） polyfill 包 |
| `ReferenceError: process is not defined`（浏览器里） | 依赖里直接用了全局 `process` | esbuild `--inject` 注入 `process` / `Buffer` |

### 5.3 HTML 外链检查

```bash
grep -c -E "https?://" web/ketcher-test.html      # -> 0
grep -o -E "(src|href)=\"[^\"]*\"" web/ketcher-test.html
# href="./ketcher/ketcher-app.css"
# src="./ketcher/ketcher-app.js"
```

**HTML 里 0 个 `http(s)://`，两条引用都是相对路径。**

`ketcher-app.css` 里有 13 处 `http://www.w3.org/2000/svg`：经逐条定位确认，它们**全部位于
`url("data:image/svg+xml;charset=utf-8,...")` 的 data URI 内部**，是 SVG 的 XML 命名空间声明，
不是网络地址，浏览器不会发起请求（下面的 5.4 抓包已证实）。

`ketcher-app.js` 里的 `http(s)://` 字样同理：XML 命名空间、开源许可证注释、以及报错提示文案里的文档链接
（如 `https://reactjs.org/docs/error-decoder.html`），都不是运行时拉取。

## 六、遗留问题 / 注意事项

1. **必须走 HTTP 打开，不能双击 `file://`**。
   引擎用 `blob:` URL 起 Web Worker，`file://` 下属于不透明源（opaque origin），Worker 会被浏览器拒绝。
   请通过本项目的本地服务（`app/` 里的 8765 端口服务，或调试用的 8899）访问。
2. **`ketcher-app.js` 有 29.6 MB**，首次加载需解析约 0.8 s（实测）。这是"零外部依赖"的代价：
   Indigo 的 11.8 MB WASM 被 base64 内嵌进了 JS。
   若以后想瘦身，可改用 `ketcher-standalone/dist/binaryWasm` 变体（WASM 单独成文件、不 base64），
   预计可降到约 18 MB，但需要额外配置 WASM 的加载路径，本次未采用以保证"绝对不会有路径问题"。
3. **只集成了小分子画板**：入口里设了 `disableMacromoleculesEditor: true`。
   代码里仍留有高分子编辑器相关的字符串（如按 PDB ID 联网取结构用的 `https://files.rcsb.org/download/`），
   但**已随该开关关闭入口，实测也不会发起这类请求**（见 5.4 抓包）。如需彻底剔除，得改打包配置，本次没做。
4. **重建依赖留在 `tools/tmp/`**（`node_modules` 约 426 MB）。`web/` 里是纯静态产物，
   删掉 `tools/tmp/` 不影响运行；要重新打包再按第四节步骤来即可。
5. `ketcher-app.js` 里含第三方开源许可证声明（Apache-2.0 等）。本次用了 `--legal-comments=none`
   去掉注释，**正式发布前建议补一个 THIRD-PARTY-LICENSES 文件**（Ketcher 为 Apache-2.0，Indigo 亦为 Apache-2.0）。
